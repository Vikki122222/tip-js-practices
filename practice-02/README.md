Значения `null` и пустая строка `""` являются самостоятельными значениями и не заменяются значением по умолчанию. |

### Как был исправлен второй эксперимент

Изначально стрелочная функция `square` имела тело в фигурных скобках, но не содержала оператора `return`:

```js
const square = (value) => {
  value * value;
};
```

До исправления вызов:

```js
console.log(square(4));
```

выводил:

```text
undefined
```

После добавления `return` функция стала выглядеть следующим образом:

```js
const square = (value) => {
  return value * value;
};
```

После исправления результат:

```text
16
```

Причина заключается в том, что при использовании фигурных скобок в стрелочной функции значение необходимо возвращать явно.

## 4. Модель данных и функции

Для работы с задачами используется модель со следующими полями:

- `id` — уникальный положительный безопасный целочисленный идентификатор задачи;
- `title` — название задачи;
- `completed` — состояние выполнения задачи;
- `priority` — приоритет задачи: `low`, `medium` или `high`.

При создании новой задачи значение `completed` устанавливается в `false`, а приоритет по умолчанию равен `medium`.

Успешное создание задачи возвращает объект с `ok: true` и созданной задачей. Операции изменения списка возвращают `ok: true` и новый массив `tasks`.

При некорректных данных операция возвращает `ok: false` и строку с описанием ошибки.

### Реализованные функции

В `src/task-service.js` реализованы девять обязательных функций:

- `createTask` — создание новой задачи;
- `findTaskById` — поиск задачи по идентификатору;
- `getPendingTasks` — получение невыполненных задач;
- `getTaskTitles` — получение названий задач;
- `getTaskStats` — расчёт статистики;
- `addTask` — добавление задачи;
- `setTaskCompleted` — изменение состояния выполнения;
- `renameTask` — изменение названия;
- `removeTask` — удаление задачи.

### Распределение ответственности между файлами

- `src/data.js` — содержит общий набор `demoTasks`, номер индивидуального варианта и массив `variantTasks`;
- `src/task-service.js` — содержит основную логику создания, поиска, чтения, добавления, изменения и удаления задач;
- `src/main.js` — запускает общий и индивидуальный демонстрационные сценарии и выводит результаты;
- `checks.js` — содержит автоматические проверки функций и собственные проверочные сценарии;
- `examples/functions-and-references.js` — содержит шесть учебных экспериментов с функциями, объектами, массивами и ссылками;
- `package.json` — содержит настройки ES-модулей и команды запуска проекта.

### Почему `id` не равен индексу

Индекс — это позиция элемента в массиве. Она может измениться после добавления или удаления других элементов.

`id` — это идентификатор конкретной задачи, который не зависит от её позиции в массиве. Поэтому для поиска, изменения и удаления задач используется `id`, а не индекс.

Например, задача с `id = 10` не обязана находиться в элементе массива с индексом `10`.

### Почему `getTaskStats` возвращает число

Функция `getTaskStats` отвечает за вычисление статистики и возвращает числовое значение `progress` без предварительного округления.

Округление выполняется только при отображении:

```js
progress.toFixed(1)
```

Это позволяет не терять точность внутри вычислений.

Для пустого списка значение `progress` равно `0`.

### Какие объекты копируются при изменении задачи

При изменении задачи создаётся новый массив.

Для изменяемой задачи также создаётся новый объект. Неизменённые задачи могут использоваться повторно, так как их свойства не меняются.

Таким образом, исходный массив и исходный объект изменяемой задачи сохраняются без изменений.
