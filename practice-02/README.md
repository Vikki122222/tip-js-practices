## 4. Модель данных и функции

Для работы с задачами была создана модель со следующими полями:

- `id` - уникальный идентификатор задачи;
- `title` - название задачи;
- `completed` - состояние выполнения;
- `priority` - приоритет задачи.

Основная логика работы с задачами находится в файле `src/task-service.js`.

В файле реализованы следующие функции:

- `createTask` - создание задачи;
- `findTaskById` - поиск задачи по идентификатору;
- `getPendingTasks` - получение невыполненных задач;
- `getTaskTitles` - получение названий задач;
- `getTaskStats` - получение статистики;
- `addTask` - добавление задачи;
- `setTaskCompleted` - изменение состояния выполнения;
- `renameTask` - изменение названия;
- `removeTask` - удаление задачи.

Успешные операции возвращают результат с `ok: true`, а при ошибке возвращается `ok: false` и описание ошибки.

### Почему `id` не равен индексу

Индекс - это позиция элемента в массиве. Она может измениться после удаления или добавления других задач.

`id` - это идентификатор конкретной задачи, который остаётся постоянным. Поэтому для поиска и изменения задач используется именно `id`.

### Почему `getTaskStats` возвращает число

Функция `getTaskStats` отвечает только за вычисление статистики. Она возвращает числовое значение `progress`.

Преобразование числа в строку, округление и добавление символа `%` выполняется уже при выводе результата.

### Какие объекты копируются при изменении задачи

При изменении задачи создаётся новый массив и новый объект только для изменяемой задачи.

Остальные задачи остаются без изменений. Благодаря этому исходный массив не изменяется напрямую.
